# Citation/Reference Infrastructure — Feasibility Notes

Phase 3 mechanical retrieval. Facts only; buildability judgment left to architect.

## 1. Scholarly metadata/search API comparison

| API | Returns | Auth / key | Rate limit | Cost | Licence/terms for caching |
|---|---|---|---|---|---|
| **Semantic Scholar (S2)** | Metadata, abstracts, citation graph (citations/references), some TLDRs; full text only via links out | API key optional, recommended | Unauthenticated: 5,000 req/5min shared pool. With key: 1 req/s on search/batch/recommend endpoints, 10 req/s others; bulk **Datasets API** for local mirroring | Free | Limited, non-exclusive, non-transferable licence to access/display S2 data per ToS; key must not be shared outside org ([S2 usage docs](https://semanticscholar.readthedocs.io/en/latest/usage.html), [release notes](https://github.com/allenai/s2-folks/blob/main/API_RELEASE_NOTES.md)) |
| **CrossRef REST API** | Bibliographic metadata (title/authors/DOI/journal/dates/funders/licence URLs), no abstracts/full text generally | None required; add `mailto` for "polite pool" | Public/polite pool ~50 req/s per IP (revised policy effective Dec 2025); polite pool prioritized with contact info in header | Free (paid Metadata Plus tier exists for high volume) | Metadata is intended to be freely reusable; expects "polite" caching behaviour, not hammering the API ([Crossref rate-limit announcement](https://www.crossref.org/blog/announcing-changes-to-rest-api-rate-limits/), [access & auth docs](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/)) |
| **OpenAlex** | Metadata, abstracts (as inverted index), citation graph, concepts/topics, OA status per work; ~60M cached full-text PDFs/XML via separate paid content API | API key required (free tier); `mailto`/"polite pool" pattern like Crossref | 100 req/s cap; free key ~100k req/day | Free for metadata; full-text content API is $0.01/file (~100 free/day on $1/day plan) | **Data itself CC0** (public domain) — cleanest reuse terms of the group; content API PDFs carry the *source* article's own licence, not CC0 ([rate limits docs](https://docs.openalex.org/how-to-use-the-api/rate-limits-and-authentication), [licence](https://github.com/ourresearch/openalex-docs/blob/main/license.md), [full-text PDFs](https://developers.openalex.org/download/full-text-pdfs)) |
| **PubMed E-utilities** | Metadata + abstracts for MEDLINE-indexed biomedical/exercise-science literature; no full text (that's PMC, separate) | API key optional (NCBI account) | 3 req/s without key, 10 req/s with key; higher on request | Free | E-utilities is the *sanctioned* automated-retrieval channel; downstream reuse of each article's abstract/text still governed by that article's own copyright notice — NCBI explicitly disclaims responsibility ([NCBI APIs](https://www.ncbi.nlm.nih.gov/home/develop/api/), [PMC developer terms](https://pmc.ncbi.nlm.nih.gov/tools/developers/)) |
| **Europe PMC** | Metadata, abstracts for ~33M works; full XML full text **only for the OA subset** (~6.5M of ~10.2M "full text available") | None required | 10 req/s (500/min) per IP | Free | No explicit blanket licence beyond respecting each work's own OA licence; well suited to sports/exercise/nutrition since it aggregates PubMed+preprints+Agricola ([Europe PMC RESTful service](https://europepmc.org/RestfulWebService)) |
| **CORE** | Metadata + full text aggregated from repositories/OA journals | API key required (email signup) | Search: 5 req/10s single, 1 req/10s batch; article-get similar | Free tier; paid tiers for scale | CORE aggregates but **does not own rights** — each item retains its original repository/journal licence, user must respect it ([CORE API docs](https://core.ac.uk/documentation/api), [CORE services](https://core.ac.uk/services/api)) |
| **SportRxiv (OSF preprints)** | Preprint metadata + full PDF (author-deposited, pre-peer-review) | OSF has a general API; SportRxiv itself has no documented dedicated API — moved off OSF infra to its own OJS/OPS platform in 2021 | Not documented for SportRxiv specifically | Free | Preprints deposited voluntarily by authors, typically openly licensed (CC-BY or similar per OSF norms), but **not peer-reviewed** — usable as a lead, not as the evidence-grade citation itself ([SportRxiv](https://sportrxiv.org/index.php/server), [DOAR listing](https://doapr.coar-repositories.org/repositories/sportrxiv/)) |

**Best single backbone:** **OpenAlex**, for three reasons: (1) metadata + abstracts + citation graph in one call, (2) explicit **CC0** licence on the metadata layer removes copyright ambiguity for the "claim → paper → metadata" store itself, (3) free at project scale (100k req/day). Layer **Europe PMC** alongside it for retrieving OA full text/abstracts on exercise-science/nutrition specifically (it indexes PubMed + preprints + patents in one place), and use **CrossRef** as a DOI-resolution fallback. (inference, based on the licence/coverage comparison above)

## 2. Open-access reality for exercise science & nutrition

| Question | Finding | Source |
|---|---|---|
| Field-wide OA baseline (biomedicine) | >50% of biomedical papers are freely available somewhere (Green/Gold/Hybrid); overall scholarly literature ~28% OA, rising to ~45% for most recent years studied | [Piwowar et al., "The State of OA", PeerJ](https://peerj.com/articles/4375/) |
| Sports-medicine-specific transparency | Meta-review of top 5 sports-medicine journals (2022 cohort): only **9% of studies had open-access data**, 22% had a data-availability statement, 12% preregistered | [PubMed 37860866](https://pubmed.ncbi.nlm.nih.gov/37860866/) |
| MSSE (Medicine & Science in Sports & Exercise) | Subscription/paywalled (ACSM/Wolters Kluwer); abstracts free via PubMed | [ACSM journal page](https://acsm.org/education-resources/journals/medicine-science-in-sports-exercise/) |
| JSCR (Journal of Strength & Conditioning Research) | Subscription/paywalled (Lippincott/NSCA) | [Wikipedia summary](https://en.wikipedia.org/wiki/The_Journal_of_Strength_and_Conditioning_Research) |
| *Sports Medicine* (Springer) | Hybrid — subscription by default, OA only if author pays APC; sister journal *Sports Medicine – Open* is fully OA | [Sports Medicine — Open](https://sportsmedicine-open.springeropen.com/) |
| AJCN (American Journal of Clinical Nutrition) | Hybrid; original articles become free-to-read **12 months post-publication**; immediate OA optional for a fee | [ASN Elsevier partnership](https://nutrition.org/publications/elsevier-partnership/) |
| Abstracts when full text is paywalled | PubMed/Europe PMC abstracts are free regardless of the underlying article's paywall status — PubMed is fundamentally a citation+abstract index, not a full-text host | [PSU library guide](https://psu.libanswers.com/faq/407955) |

**Practical read:** Abstracts plus bibliographic metadata are reliably obtainable for essentially the whole field (PubMed/Europe PMC/OpenAlex cover it). Full text is the constraint — for the flagship journals in this niche (MSSE, JSCR, *Sports Medicine*) it's paywalled by default; AJCN opens after a 12-month embargo; only *Sports Medicine – Open*, BMC Sports Science, and similar OA-native titles give full text immediately. A solo dev can legally build the "claim → citation" layer entirely off abstracts + metadata; getting the *numbers inside a paywalled full-text figure* (e.g., an effect size buried in a table, not the abstract) will often require reading it via institutional/library access and manually transcribing the fact, not through open APIs. (inference — no single source states this "abstract-only" gap for the specific niche journals above)

## 3. Copyright — what can actually be reproduced in-app

| Case | Verdict | Principle / source |
|---|---|---|
| **(a) Facts/data extracted from a paper** — sample size, effect size, p-value, mean±SD | **Can reproduce.** Facts and data are not copyrightable in either the US or UK; only the *original expression* around them (prose, selection/arrangement) is protected. | *Feist Publications v. Rural Telephone* (US, 1991): "facts are not copyrightable... [n]o author may copyright his ideas or the facts he narrates" ([Justia](https://supreme.justia.com/cases/federal/us/499/340/)). Confirmed generally for research data: "data gathered through experiments, research, surveys... is not protected by copyright" ([Saxton Stump](https://www.saxtonstump.com/news-and-insights/how-copyright-law-applies-to-data-and-scientific-papers/)). **UK caveat:** the EU/UK *sui generis* database right (Copyright and Rights in Databases Regs 1997) can still restrict **systematic/repeated extraction of a substantial part of someone's database** even though the individual facts aren't copyrighted — relevant if scraping large structured tables wholesale rather than transcribing individual numbers by hand ([Sprintlaw UK](https://sprintlaw.co.uk/articles/understanding-sui-generis-database-rights-in-the-uk/)). Conservative reading: extracting a handful of numbers per paper by hand for a curated claims DB is safe; bulk-scraping an entire proprietary table/dataset wholesale is the riskier edge case — get real legal advice before doing that at scale. |
| **(b) Quoting sentences from a paper** | **Can, within limits.** UK: fair dealing for quotation (CDPA s.30A) and for criticism/review (s.30) permit quoting provided the use is "fair" (proportionate, doesn't substitute for the original, properly attributed) ([Wikipedia: Fair dealing in UK law](https://en.wikipedia.org/wiki/Fair_dealing_in_United_Kingdom_law), [UCL copyright blog](https://blogs.ucl.ac.uk/copyright/2014/05/01/new-quotations-exception-due-1st-june-2014)). US: fair use four-factor test (purpose/nature/amount/market effect), with short factual quotations for informational/transformative purposes generally favoured ([US Copyright Office](https://www.copyright.gov/fair-use/)). Conservative reading: a one-sentence attributed quote of a paper's conclusion is low-risk; quoting several paragraphs or the discussion section verbatim is not. |
| **(c) Reproducing a figure/chart from a paper** | **Cannot, without permission — the highest-risk case.** A published figure is the *authors'/publisher's original expression* (design, layout, exact visual), not a bare fact, so it's copyrighted independent of the data it displays. STM Permissions Guidelines (adopted by Elsevier and other major publishers) allow free reuse of **up to 3 figures/tables per source article** between STM signatory publishers only — that carve-out does not extend to a commercial app outside that publisher network, which needs to go through RightsLink/permission request, sometimes with a fee ([Elsevier permissions](https://www.elsevier.com/about/policies-and-standards/copyright/permissions), [STM Guidelines PDF](https://supportcontent.elsevier.com/Support%20Hub/Author%20Book%20Publishing/Permissions-Guidelines-June-26-2024.pdf)). **Conservative/practical path for "surfacing figures":** re-plot the underlying numbers as a new chart in the app's own visual style, sourced to the paper, rather than screenshotting/embedding the original image — this sidesteps the figure-copyright issue by using only the (uncopyrightable) data, not the publisher's expression of it. This is the load-bearing legal conclusion for the product's "surface figures" feature. |
| **(d) Citing bibliographic metadata** (title/authors/DOI/journal) | **Can reproduce freely.** This is exactly what CrossRef/OpenAlex/PubMed exist to distribute; DOIs/titles/author lists are factual identifiers, not expression, and all the APIs above are built for exactly this reuse. No source found asserting any restriction here. | (see API table, §1) |

**Bottom line for the crux question:** "surface the actual figures" (verbatim image reuse) is legally the shakiest option and should be treated as **must re-plot**, not reproduce, absent a paid permission/licence. Extracted numbers, quoted short passages (attributed), and bibliographic metadata are all on solid legal footing under the facts/expression distinction. **This is not legal advice** — before shipping a feature that reproduces any publisher-owned visual asset, or before bulk-scraping structured data tables at scale, get this reviewed by an actual IP/copyright solicitor, especially given the UK sui generis database-right wrinkle that has no clean US equivalent.

## 4. Buildability

- **Scope check (50–150 core claims, solo, 2–3 months):** Per-claim work = find 1–3 supporting papers (via OpenAlex/Europe PMC search), pull metadata, read abstract (often enough) or source full text where accessible, hand-extract 2–4 key figures (n, effect size, CI/p, population), assign an evidence grade, write the app-facing claim text. At even 30–45 minutes/claim once tooling exists, 100 claims ≈ 50–75 hours of pure research labour — realistic to fit in a 2–3 month solo v1 *if* it's the primary deliverable of that period, not a side task alongside building the rest of the app. (inference — no source sizes this specific workflow; time-per-claim is an estimate, not measured)
- **Where the API layer actually helps:** it removes the metadata/citation-graph lookup labor (search, DOI resolution, checking OA status) — it does **not** remove the manual full-text reading + numeric extraction + grading step, which is inherently human judgment (the app's core value-add and its main cost).
- **Maintenance burden:** ongoing, not one-time. New meta-analyses supersede old ones; retraction/correction watch is needed (OpenAlex and Crossref both expose retraction flags); a "last verified" date per claim and a lightweight re-check cadence (e.g., quarterly re-query per claim topic against OpenAlex for newer citing meta-analyses) is the realistic minimum. This is a standing content-ops job, not a "build once" task — sizing the recurring effort is for the architect. (inference)
