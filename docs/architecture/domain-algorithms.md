# Domain algorithms

Pure domain code lives in `app/src/domain/`; snapshot composition lives in
`app/src/advice/snapshot.ts`. These functions are deterministic and
framework-free. They produce measurements or state for the claim engine; they
do not author advice.

| algorithm | inputs and sufficiency | output | explicit non-claim | requirements and tests |
| --- | --- | --- | --- | --- |
| Calorie guards | Sex, maintenance, and requested target/deficit. Inputs must be finite and positive; invalid input falls back to maintenance or the 1,200 kcal absolute floor. | Whole-kcal target after the 500 kcal/day deficit cap, sex floor (1,400 female/unspecified; 1,800 male, never above maintenance), then absolute floor. | Not a personal clinical prescription. No UI may calculate a second target path. | GR-1, FR-ONB-2, AC-5 · [source](../../app/src/domain/guards.ts) · [tests](../../app/src/domain/guards.test.ts) · [structural check](../../app/src/guards-enforcement.test.ts) |
| Energy estimate | Sex, height 100–250 cm, weight 30–350 kg, age 13–100, and activity level. Invalid or partial profiles return `null`. | Rounded Mifflin–St Jeor maintenance estimate and a displayed ±10% plausible range; protein target is a separate rounded 1.6 g/kg population reference. | The range is not a statistical confidence interval, observed maintenance, or advice to eat the point value. | T3, GR-4 · [source](../../app/src/domain/energy.ts) · [tests](../../app/src/domain/energy.test.ts) |
| Set e1RM and trend | Positive weight/reps, non-negative RIR; only reps ≤10 and RIR ≤3 qualify. A trend needs ≥8 points with more than one date. | Epley estimate using reps + RIR; ordinary least-squares slope in %/week, 95% t interval, fitted-mean band, and `withinNoise` when the slope interval crosses zero. | Never a point-to-point progress claim; a one-rep RIR-0 set returns the measured load exactly. | FR-SIG-1, FR-SIG-2, T3, AC-2 · [source](../../app/src/domain/e1rm.ts) · [tests](../../app/src/domain/e1rm.test.ts) |
| EWMA | Date-sorted points and a positive half-life. Weight consumers use a seven-day half-life. | One smoothed value per input date, weighted by elapsed time between irregular readings. | No interpolation or invented daily readings; the function does not sort a bad input series. | FR-SIG-4, T3 · [source](../../app/src/domain/trends.ts) · [tests](../../app/src/domain/trends.test.ts) |
| Weekly volume | Logged sets, exercise contribution maps, and inclusive seven-day start. Soft-deleted, out-of-window, and unknown-exercise rows are skipped. | Fractional totals by muscle; absent muscles are omitted rather than emitted as zero. | Population-comparable volume, not personal MEV/MRV. **Current gap:** warm-up rows are counted even though UI copy says otherwise. | FR-SIG-3, GR-4 · [source](../../app/src/domain/volume.ts) · [tests](../../app/src/domain/volume.test.ts) |
| Protein on training days | Food rows, set rows, and positive latest bodyweight. Local calendar days must contain training and logged food. | Mean of each qualifying day's total protein divided by bodyweight; otherwise `null`. | `null` means unmeasured, not zero intake; rest days are intentionally outside this metric. | FR-SIG-5, T3 · [source](../../app/src/domain/protein.ts) · [tests](../../app/src/domain/protein.test.ts) |
| Snapshot construction | Goal, goal start, preferences, 84-day weights/sets/food, exercise map, and current time. | Best qualifying e1RM per day/exercise, primary lift by most sessions, seven-day volume/protein, reconciliation, and `UserStateSnapshot`. | Plumbing, not a second judgement layer; no qualifying lift or food is represented honestly as missing. | FR-ADV-4, AC-3 · [source](../../app/src/advice/snapshot.ts) · [tests](../../app/src/advice/snapshot.test.ts) |
| Reconciliation | Goal, raw weights, qualifying session e1RMs, and goal age. Weight needs ≥4 readings across ≥14 days; e1RM uses its own ≥8-point gate. | Weight/e1RM states, verdict, unresolved signals, observed values, and confidence. High confidence needs resolved signals, ≥28 days, and ≥8 weigh-ins. | Does not diagnose rapid loss: `down_fast` is never emitted because no defended threshold exists. Falling strength requires a 95% interval excluding zero. | FR-SIG-5, T2, T3 · [source](../../app/src/domain/reconcile.ts) · [tests](../../app/src/domain/reconcile.test.ts) |

The Weekly Review loads the bounded source window and renders these results; the
claim engine remains the only route from a snapshot to claim-backed advice. See
[advice engine](advice-engine.md), [data model](data-model.md), and
[requirements traceability](../reference/requirements-traceability.md).
